# Lineage and observability privacy

Use existing GovernedService, current tenant principal/security snapshot, Project membership/shares,
resource kind adapters, pipeline binding reads and application dependency references. No new grant,
role, identity provider or policy engine exists. Roots and every reached endpoint/supporting origin
are checked independently. SQL membership pruning precedes traversal candidates and dashboard samples;
current canonical permission checks precede node disclosure and expansion.

Prune inaccessible edges and nodes without a placeholder, hidden count/name, private version/schema,
or hidden-path export. One visible dataset/output does not confer upstream, sibling, pipeline or app
access. Published application versions require all declared references; drafts are never indexed.
Canonical type/version schema access is rechecked. Private and missing roots use governed 404. A missing
tenant/security context may independently fail authentication/tenant admission before resource lookup.

The Phase 21 observation endpoint and existing DAG status suppress node metadata, plan digest and
prepared counts where complete binding visibility is absent. Committed output references remain
independently authorized. Arbitrary persisted error strings and metric metadata are not copied into
observations/events. Events use fixed state/severity and correlation identities; no environment,
credential, object key or source record is accepted by an operational event endpoint.

Session/tenant/principal isolation, CSRF enforcement, bounded metadata responses, read-only retries and
no automatic mutation retries remain in SDK/React/BFF. Exports are subject to the same response graph;
there is no privileged graph-download bypass. The implementation report lists the exact executed
security/browser coverage and any remaining acceptance limitations.
